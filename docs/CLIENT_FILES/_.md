# Client files

Where the files a client attaches are kept, and how the ERM opens them.

## Two sources

| Uploaded on     | Stored on D1.1 as         | Who can open the stored value  |
| --------------- | ------------------------- | ------------------------------ |
| IMHOGEN website | its UploadThing link      | anyone with the link (public)  |
| ERM client form | `file:<id>` (`files` row) | nobody: the ERM makes the link |

The website saves each file as `<link>,<file name>`. The intake splits it: the link goes in `fileLink`, the client's file name in `label`.

## Uploading in the ERM

- The client form (Start new project, and sending the form again after a change request) has Add files. Each file uploads the moment it is chosen, straight from the browser to UploadThing.
- The limits are the website's: images and PDFs, 16MB each, at most ten on a request.
- `/api/uploadthing` asks for a client session before each upload. UploadThing then calls back to the same route, with no session, checked by its signature; the proxy leaves that route open.
- The callback saves a `files` row: storage, key, name, size, type, the person who uploaded it, and no project yet.
- Sending the form puts the person's uploads on the project and lists them on D1.1, in the client's order. An upload that is someone else's, or already sent with another request, is refused and nothing is saved.
- An upload never sent stays with no project and is never shown.

## Opening a file

Every file opens through `/api/files/[recordId]?ref=...`. The person must be able to read the record, and the record must hold the value.

- A website link redirects to that link.
- `file:<id>` must be a file sent with the record's project. The ERM asks the storage for a link that expires after five minutes and redirects to it.

## Storage

- Files are uploaded private (`acl: "private"`). The UploadThing app must allow it: set the app's default to private, or allow overriding the ACL. If it does not, uploads fail instead of going public.
- `UPLOADTHING_TOKEN` is the app's token, kept in `.env.development` and `.env.production` with dotenvx.
- `server/files/storage.ts` is the only code that talks to the storage. Records hold `file:<id>`, never a storage link, so moving to another store, such as Cloudflare R2, means:
  1. add the store to `file_storage` and to `storages`,
  2. copy each file's bytes across under the same key,
  3. set `storage` on the copied rows.

  The website's own links on D1.1 stay on UploadThing unless they are copied and rewritten too.
