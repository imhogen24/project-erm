# IMHOGEN ERM — Technology Stack

## Pre-existing (scaffold)

- Next.js 16, React 19
- Tailwind v4, shadcn/ui (strict), mobile-first
- Phosphor Icons

## Hosting

Vercel.

## Database & ORM

Postgres (Neon) + Drizzle.

## Auth & RBAC

Better-Auth, self-hosted, Drizzle adapter. Custom 19-role + Client permission matrix (`docs/dev_docs/CRITICAL_DATA_STRUCTURE/PERMISSIONS.md`) needs to live in our own schema; avoids per-MAU billing.

## File Storage

Cloudflare R2. S3-compatible, free egress permanently, 10GB free tier.

## Email

Resend.

## Background / Scheduled Jobs

Inngest. 50k executions/mo free, hard cap, no overage billing.

## Frontend Data Fetching / State

Server Actions + React Server Components by default. TanStack Query deferred — add later, scoped to a specific screen (e.g. the Pr2.1 Gantt chart), only if it needs live client-side updates.

## Forms & Validation

Zod + React Hook Form.

## Testing

Vitest (unit/integration) + Playwright (e2e).

## Package Manager

bun, per `AGENTS.md`. Repo currently has `pnpm-lock.yaml` checked in — reconciling this is implementation work, not done here.

## Contract Signing / E-Signature

Internal approve/sign flow. Stores a hash of signer + timestamp + content as `digital_signature_hash` (`docs/dev_docs/CRITICAL_DATA_STRUCTURE/METADATA_CAPTURE.md`). Not a third-party e-signature vendor.

## PDF Generation

React-PDF for generating certificates/handover docs from React components. pdf-lib for merging/assembling existing PDFs — needed for D10.3 (Final TDP Manifest), which combines multiple certs, drawings, and reports into one package.

## Linting & Formatting

ESLint (`eslint-config-next`, React Hooks rules) + Prettier (`prettier-plugin-tailwindcss` for class sorting) stay as the source of truth. Oxlint added alongside for fast local/pre-commit checks — it doesn't replace ESLint's Next.js-specific or Tailwind-sorting coverage, just runs ahead of it. Biome rejected: unverified Tailwind class-sorting support and no Next.js-specific rule set, too much risk for a project mandated to use shadcn/Tailwind strictly.

`@shadcn/lint` added on top of ESLint + Oxlint to enforce the existing "strictly shadcn" rule (`AGENTS.md`) automatically — catches restyled components, raw colors, arbitrary Tailwind values, inline styles, and invalid classes.

## Environment Variables

dotenvx (`@dotenvx/dotenvx` + `@dotenvx/next-env`, overriding `@next/env`). Single `.env.development` file, committed to git encrypted — no `.env.local`/`.env.production` split for now. The decryption private key lives in the OS native secret store by default; `.env.keys` (gitignored) is the portable fallback used to hand the key to a teammate or set it in CI/Vercel as `DOTENV_PRIVATE_KEY_DEVELOPMENT`.

## Git Hooks

Lefthook, pre-commit only. Runs, in order: re-encrypt `.env.development` if staged (`bun run encrypt`, restaged automatically), `dotenvx protect` as a hard guard, Prettier on staged `.ts`/`.tsx` files (auto-fixed and restaged), then `bun run lint` and `bun run typecheck` project-wide (block the commit on failure, no auto-fix). Installed automatically via `postinstall` so every teammate gets it on `bun install`.

`dotenvx protect` additionally registers a git clean filter so plaintext `.env.development` can't even be `git add`ed. Its own CLI hardcodes this registration to **global** git config (`~/.config/git/config` + a global `core.attributesFile`) — which affects every repo on the machine and hardcodes a path into this repo's `node_modules`. We don't want that: `scripts/setup-git-filter.mjs` (run via `postinstall`) registers the same filter in **local** `.git/config` instead, scoped to this repo only, paired with a committed `.gitattributes`.

## Observability

Sentry.
