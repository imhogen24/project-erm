# UI context

How every screen in the ERM looks and behaves. Read this before you build or
change a screen, and load the `frontend-design` skill. The rules here are
decisions already made; follow them before inventing anything new. When a rule
here and a skill disagree, this file wins.

The live reference is the code named in each section. If a pattern you need is
missing, add it to the shared place (a CSS variable or class in
`app/globals.css`, or a component in `components/`) and add a line here.

## 1. Layout

- **The drafting grid.** Every page sits on `.drafting-grid`. One major square
  is `--cell` (96px from 640px up). The grid is centred: the leftover width is
  split between the two sides, so the gap left of the sidebar equals the gap
  right of the page.
- **Sidebar and page.** On wide screens the sidebar (`.sidebar-frame`) is three
  squares wide, one square in. The page (`.table-project` or `.table-wide`)
  starts one square after it and stops one square before the right edge.
- **One sheet per page.** Draw every page with `PageSheet`
  (`components/page-sheet.tsx`): title over a ruled line, then the body, at
  least as tall as the sidebar. Page-wide buttons go in its `actions` slot, at
  the right of the title. Tool pages use `ToolSheet`, which follows the same
  rules.
- **Tiles fill the sheet.** A grid of tiles uses `flush` and shares the
  sheet's lines; rows share spare height so no empty strip is left at the
  bottom (see `app/(app)/page.tsx`).
- **Full width.** No empty right half. No `max-w-*` that leaves a blank column
  inside a sheet.
- **Mobile first.** Nothing scrolls sideways at 375px. Rows of a table become
  stacked cards on narrow screens.

## 2. Colour and tokens

- Use the CSS variables in `app/globals.css`. Never a one-off value such as
  `bg-foreground/[0.04]`, `bg-primary/20` or a raw hex in a component.
- Surfaces: `--surface-tile`, `--surface-tile-hover`, `--surface-chosen`,
  `--surface-note`, `--surface-inset`. Chips: `--chip-open`, `--chip-done`.
  Borders of fields: `--input`.
- Colour means something, the same thing everywhere:
  - **Orange** (`--primary`): needs action, or chosen, or good (a tick).
  - **Red** (`--destructive`): failed or refused.
  - **Grey**: everything else.
- Check light and dark. A token must read in both; never fix one theme with a
  colour that breaks the other.

## 3. Shapes and borders

- Grid boxes, sheets and tables are square (`--radius: 0`).
- Controls are softly rounded with `--radius-control`: buttons, fields,
  selects, chips, badges, tiles, avatars. Never a circle unless it is a radio,
  a dot or a count.
- No borders inside a grid square. Set things apart with a fill
  (`.tile`, `.note-panel`, `.inset-row`), not a frame inside a frame.
- To tint a box that draws grid lines with shadows, use a background layer,
  never `box-shadow`.

## 4. Shared parts

Reuse these; do not rebuild them.

| Need                                    | Use                                           |
| --------------------------------------- | --------------------------------------------- |
| A page                                  | `PageSheet`                                   |
| A tool's state                          | `StateBadge` (`.state-badge`)                 |
| A status that needs someone, or is done | `.status-chip` (`data-open`)                  |
| A result, such as a file's status       | `FileStatusChip` (`.result-chip`)             |
| One choice of a few short options       | `SegmentedChoice` (`.segmented`)              |
| One choice with an explanation          | `.tile-choice` with a radio                   |
| Several choices                         | `.tile-choice` with a checkbox                |
| A select option with detail             | `OptionRow` (mark, name, grey detail)         |
| A table of answers                      | `TableBox` / `DataTable`, or `TableEditor`    |
| A filled area                           | `.tile`, `.note-panel`                        |
| A button on a tile                      | `.tile-action`                                |
| A person                                | `Avatar` with `initialsOf` and `.avatar-soft` |
| A sidebar link                          | `.nav-link`, `.nav-tool`, `.nav-project`      |

UI components come from shadcn (`components/ui/`). Pages stay Server
Components; put `"use client"` on the leaf that needs it.

## 5. Controls and forms

- **One height.** Fields, selects and the button beside them are
  `--control-height` (48px). In a table row every field starts one line tall
  and the row reads level; a long answer grows as it is typed.
- **Selects** open below the field at its width, on a solid surface. Rich
  options use `OptionRow`, and the chosen option shows the same way in the
  closed field.
- **Choices show their meaning.** The chosen option fills with what it means
  (Pass orange with a tick, Fail red with a cross). Never a grey fill that
  says nothing.
- **Locked means read.** On a locked record, fields read as plain text with no
  box and no placeholder; the chosen option stays bright and the others fade.
- **No hint that repeats a label.** If a column or label already names the
  field, leave the placeholder out.
- **Labels and names stay stable.** Keep accessible names (`aria-label`,
  button text) when you restyle; the e2e tests find controls by them.

## 6. Behaviour

- **A tile that opens something opens from anywhere on it.** Use
  `.stretched-link` (or `.tile-cover` when the visible link is a button) on a
  `.link-tile`. Controls inside sit above it with `.above-stretch` or
  `.above-stretch-row`. The whole tile tints on hover and shows focus.
- **What cannot be used is not a link.** A tool that cannot open yet is
  greyed, says what it waits on, and its address leads back to the project.
- **One project tier.** A Tier 1 project never shows a T3 tool; a Tier 3
  project shows the T3 tool in place of the one it replaces.
- **Keyboard and motion.** Every control is reachable by Tab with a visible
  focus ring. Motion respects `prefers-reduced-motion`.

## 7. Words

- Sentence case. No all-caps labels, no label above every heading.
- Name things the way the person knows them: the role in full where it helps
  ("PM Project Manager"), the operand's name under its letter.
- A button says what happens: "Submit for approval", "Create invite",
  "Assign". The same action keeps the same name everywhere.
- An empty state says what to do next ("Nothing here yet. Press Add row to
  start the list.").
- Errors say what went wrong and how to fix it. They do not apologise.
- Do not invent facts. Labels, role titles and option names come from the
  definitions or `docs/`; if they are not there, ask.

## 8. Before you say it is done

1. Typecheck and lint pass.
2. Look at the screen in a browser: light, dark, and 375px wide.
3. Check nothing overlaps, sticks out of its cell, or scrolls sideways.
4. Check every new colour, radius and size uses the tokens and shared parts
   above.
5. Add the screen to `scripts/db/preview.ts`: who to log in as, the route, what
   should be there.
6. Make sure the seed data shows the screen with realistic content
   (`scripts/db/seed-data/`); no "Demo" names.
7. Tell the user who to log in as and which route to visit.
