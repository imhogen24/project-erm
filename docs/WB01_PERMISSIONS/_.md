# WB01 permissions

Who sees each Workbook 1 (Project Onboarding & Definition) tool, and what they can do with it. Read this before building a WB01 tool.

## The letters

| Letter | Means                                                                 |
| ------ | --------------------------------------------------------------------- |
| `-`    | The role does not see the tool at all: no tile, no screen, not found. |
| `RO`   | Read only.                                                            |
| `RW`   | Read and write: the role fills the tool in.                           |
| `RA`   | Read and approve: the role reviews the tool and can approve it.       |

`RA` does not by itself say who locks a tool. How a tool locks, and who does it, is decided when the tool is built (below).

## Where it lives

- The code: `server/permissions/matrix.ts`, one row per tool.
- The full matrix for every workbook: `docs/dev_docs/CRITICAL_DATA_STRUCTURE/PERMISSIONS.md`. A test fails if the code and that file differ.
- Every check is on the server. A screen hides what a role cannot do, but the action refuses it again.

## Who locks each tool

Decided per tool when it is built. `extraApprovers` in `matrix.ts` names a role that approves a tool it only reads.

| Tool     | Locks when                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| D1.1     | The client sends the web form. Nobody approves it.                                                                              |
| D1.2     | The PM approves the OM's triage.                                                                                                |
| D1.3     | The PM approves (RA).                                                                                                           |
| D1.4     | The PM presses Send.                                                                                                            |
| D1.5     | The OM submits after the client has chosen a time. Nobody approves it.                                                          |
| D1.6     | The OM presses Ready for the meeting, once the calendar invite is sent and every pre-meeting check is done. Nobody approves it. |
| D1.7     | The PM approves the OM's submitted notes. The PM may instead send them back to the OM with a reason.                            |
| D1.8     | The PM approves once the Lead Engineer has signed and submitted. The PM may instead send it back.                               |
| T3.D1.8a | The LE approves once the AE has signed as Lead Measurer and submitted. The LE may instead send it back.                         |
| D1.9 on  | The `RA` role approves, until each tool is built.                                                                               |

Any approver can send a submitted record back to its writer instead of approving it (`sendBackRecord` in `server/records`). It becomes a draft again, the reason is kept in the audit log and shown above the sheet, and whoever submitted it gets a dashboard notification.

## The client

On D1.8 the Lead Engineer sees the client's technical answers from the web form (inputs, outputs, operators) beside the 2.0 categories, though they do not read D1.1: never the client's contact details.

The client is `RO` on D1.7, but sees nothing on it until the PM approves it: before then it holds IMHOGEN's working notes. A tool marks this with `clientReadsOnceLocked`.

A client never replies by email. Every client step in WB01, such as choosing a meeting slot on D1.5, is a screen on their dashboard; emails to the client only tell them there is something to do.

A step like this is not a write to the sheet. On D1.5 the client is `RO`: they read the times sent, and their own screen lets them choose one or propose another, through `chooseMeetingTime` and `proposeMeetingTime` (`server/meetings`). Those fill only D1.5's system fields (the chosen slot, their comment, the time they proposed), only while D1.5 is a draft with times sent, and only for a Client on the project. Nothing else on D1.5 is theirs to change.
